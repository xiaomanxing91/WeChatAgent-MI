# 图片与表情任务隔离

本次修改保留原 DSH 会话，不需要为图片错误归档重开。

- 收到的图片最多两张并发，仍按原消息顺序提交。整批读取预算 25 秒，单图预算 12 秒；模型信息解析、读取和附件保存均受截止时间约束。
- 后台图片工作进程含排队时间最多 11 秒，最多两个工作进程、四个在途任务；超时终止工作进程，排队超时不再启动。失败时保留文字与图片未读取的说明。
- 未标注的候选图库素材不再随普通文字同步送入识图。明确要求发表情时可读取至多两张预览，用户实际收到的图片仍正常识别并学习标签。
- 文字部分先按原顺序发送，表情进入独立持久化队列。表情队列不占用会话的模型处理锁；发送、重试与回执核对在后台进行。
- 每张待发表情最多保留 45 秒，每个会话最多三个待发任务、全局最多 64 个。额度不足、资源失败、超时或关闭开关时终结配图，并保留真实发送状态说明。发送限额继续生效。
- 已提交或响应丢失的表情只查询回执，不重新提交。终结后释放发送器中匹配的旧回执占位，保存不允许重发的操作记录；重启后的过期任务也会清理。
- 已确认的文字与表情不重发。迟到 RPC 结果不更新已终结的任务。已提交给微信的消息无法撤销，程序不会将未知结果伪报为成功。
- 模型失败、取消和超时轮次中的图片会从后续模型请求中卸载，原始历史与附件引用仍保留，避免同一坏图持续污染后续文字请求。客户端断开时取消对应模型任务并释放本项目的请求状态。
- 当前模型不支持图片，或图片校验失败时，丢弃图片字节并保留“未读取”的文字占位。模型明确拒绝带图请求或带图轮次超时后，桥接端只进行一次无图降级，不重复联网或图库工具调用，避免同一张未处理图片反复堵住消息队列。

测试只使用离线模型、模拟发送器和加密测试数据库，不向真实联系人发送测试消息。网络中断、DSH 进程崩溃和微信拒绝仍会影响回复，但图片与表情任务不会无限占住本项目的会话队列。
