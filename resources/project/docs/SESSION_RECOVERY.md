# 系统消息头错误与会话恢复

适用错误：`SessionFormatError: system/message requires a protected first surface head`。

旧版扩展说明可能在新会话的首次 `agent/pre-step` 中直接追加为用户消息。DSH 尚未写入受保护的系统消息头，后续保存的历史因此可能无法重新加载。修正后，首次说明随原生消息接纳流程写入；已有说明继续在原位置更新，不逐轮重复添加。

## 在安装设备上恢复

1. 更新到包含此修复的 WeChatAgent 文件。已有安装包不会因源码更新而自动改变。
2. 从托盘完整退出 DSH，再重新打开，加载更新后的本地插件。
3. 在 WeChatAgent 的“会话”中为对应聊天点击“初始化会话”或“同步名称”。

插件恢复旧会话时，如果 DSH 明确报告上述系统消息头错误，会先保存旧会话映射和配置，再建立替代会话。新会话创建成功后才更新当前映射；创建失败时继续保留旧映射，重试不会覆盖备份。

备份位于工作目录的 `state/dsh-session-recovery/social-会话摘要.json`，包含旧会话 ID、对应聊天、原会话配置和恢复原因。DSH 的原始 `session.v4.jsonl.zstd` 文件保持原样，不删除、不改写。

替代会话不继承损坏历史的上下文。历史加载错误不等于聊天内容已经丢失；如需进一步恢复原历史，需要保留完整会话目录。旧会话在 DSH 中仍可能显示加载错误，请打开新建的对应微信会话继续使用。

此处理仅匹配系统消息头缺失这一项错误。工具重名、模型凭据、其他格式错误不会自动换会话，继续保留具体错误供排查。

## 验证

维护者在开发环境运行 `node --test scripts/test-native-session.mjs`，覆盖空会话首次写入、多步骤与重启、旧会话恢复、备份保留、创建失败后重试，以及不相关错误不换会话。

`scripts/verify-dsh-runtime.cjs` 使用真实 DSH 运行时、隔离存储和离线模型，验证压缩日志保存后重新恢复，并复现旧版错误历史，确认替代会话可以继续对话、原文件摘要不变。测试不向微信发送消息。
